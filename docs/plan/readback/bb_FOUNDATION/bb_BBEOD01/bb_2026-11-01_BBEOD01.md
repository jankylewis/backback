## 2. Issue: the printed log folder stayed empty

- Observed: `bb open` printed a Roslyn log folder that held no file.
- Cause: the server sends its log as `window/logMessage`, and
  `wait_for_load` dropped every message.
- Failing test: `wait_for_load_keeps_every_server_message_in_the_log`.
- Fix (d6364b3): each message goes to a per-run `open-*.log`, and `bb open`
  prints that file. Repeat: the log showed every project load line.

## 3. Issue: `bb open` wrote into the opened solution

- Observed: run 1 wrote 3 files at 00:41:35 in
  `MbTx/MbAuto/MbDesktop/obj/Debug/net10.0/` (`_MbDesktop.AssemblyInfo.cs`,
  `.AssemblyInfoInputs.cache`, `.csproj.AssemblyReference.cache`). Runs 2-5
  wrote nothing. A later check run wrote
  `MbDesktop/bin/Debug/net10.0/.msCoverageSourceRootsMapping_MbingDesktop`.
  All are gitignored; MbTx `git status` stayed unchanged.
- Cause: Roslyn's automatic `dotnet restore`, and its design-time build
  writing `obj/` and `bin/`. Turning restore off alone was not enough.
- Failing tests: `open_by_default_tells_roslyn_not_to_restore_and_writes_nothing_in_the_solution`
  (whole-tree snapshot of path, size and mtime; failed on the restore line,
  then `obj/`, then `bin/`) and `open_with_restore_flag_lets_roslyn_restore`.
- Fix (e90d4e4): bb answers `workspace/configuration` with
  `projects.dotnet_enable_automatic_restore = false`, and sends
  `IntermediateOutputPath` and `OutputPath` to a scratch folder outside
  the solution. `bb open --restore` keeps the old behaviour.
- Proof: marker file, one default `bb open`, then `find MbTx -newer marker`
  gave 0 entries (files and folders); 0 restore lines in the log.

## 4. Issue: parallel runs shared one log file

- Observed: two `bb open` runs that started in the same millisecond wrote
  one `open-<ms>.log` (interleaved lines); an e2e test failed on it.
- Failing test: `two_logs_created_in_one_millisecond_never_share_a_file`.
- Fix (82c2f29): the log name carries pid and a counter and is created
  only if new; the scratch folder is per run and removed at exit.
  Repeat: the open e2e tests passed 3 of 3.

## Lessons

- A printed path is evidence only if something is written there: check it.
- "Restore off" is not "read-only": snapshot the whole tree, files and
  folders, before and after.
- Any per-run file name needs a run id, not a clock alone.

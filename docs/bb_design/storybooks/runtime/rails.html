08 · SAFETY RAILS

Rules that
stop bugs.

The compiler, a rule checker and the test run check these rules on every change.

1 · IN THE CODE

POSITIONSThe two kinds of position have different types. If you mix them up, the code does not build. Only one checked function changes one into the other.
TIME LIMITSEvery question to a tool, and every command, has a time limit. If a tool dies, every waiting question gets an error. Nothing hangs.
ERRORSEach package has its own list of errors. The code never hides a failure, and never crashes on purpose outside tests.
NO UNSAFEUnsafe Rust is not allowed. That is why the guard is a small shell script.
FALLBACKIf Roslyn crashes, backback tells you and offers to restart it. You can still type, and colours still work.

2 · IN THE FILES (bb-audit)

5 ITEMSNo more than 5 items in any folder.
SHORTNotes (.md) up to 100 lines. Code files up to 250 lines. A function up to 50 lines. Up to 5 inputs per function.
MARKERIn each folder, the most important item starts with bb_. Only one item per folder.
TYPESEvery Rust value says its type in the code, so a reader never has to guess.
